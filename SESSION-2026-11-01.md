### 1.2 Outbox "1 Queued" Root Cause Analysis
* **Inquiry**: Why does the dashboard show "1 Outbox Queued" in amber warning text for a long time?
* **Forensic Evidence**:
  1. `logs/copyclip.log` shows: `copyclip.outbox: outbox[node:pixel] holding 29d87b9c6fdf (target unavailable)`.
  2. `state/outbox.json` contains `{"node:pixel": {"mime": "image/png", ...}}`.
  3. `state/outbox/node_pixel.bin` holds the 44 KB binary sidecar waiting for delivery.
* **Mechanism**:
  - In `core/outbox.py`, the outbox is engineered as a durable, single-slot-per-target pending queue.
  - S24 Ultra and Tab S10 Ultra belong to the `samsung (Continuity)` domain, where delivery to one satisfies the domain.
  - Pixel 1 is an independent standalone node. When clips originate on the laptop or phone, delivery to Pixel attempts write and returns `WriteResult.UNAVAILABLE` because Pixel is offline.
  - The payload queues under key `node:pixel`. Because Pixel remains offline, `_drain_outbox()` skips it.
  - The outbox functions as designed, holding the latest clip in custody so Pixel immediately synchronizes upon reconnecting.
  - The root issue was UX ambiguity: the dashboard displayed a bare `1 Outbox Queued` without naming the target device, leading users to suspect a general sync deadlock.

### 1.3 Delivered Clips Metrics (Session Throughput vs Lifetime Odometer)
* **Inquiry**: Why does the delivered clips count reset to zero when restarting the app? Shouldn't it hold complete total numbers?
* **Architectural Evaluation**:
  - `self.stats = {"observed": 0, "delivered": 0, "skipped": 0, "queued": 0}` in `core/hub.py` is an in-memory dictionary.
  - Design Rationale:
    1. Zero SSD write amplification: high-frequency clipboard sync does not write metadata to disk on every event.
    2. Real-time liveness health check: an uptime counter starting from zero proves the current daemon process is actively pumping clips. A permanent odometer showing 14,000 hides whether the background process is running or frozen.
  - Usability Issue: The label `Clips Delivered` was ambiguous. Users interpreted it as a cumulative lifetime odometer.
  - Resolution: Updated label to `Session Delivered` with an uptime throughput caption to align expectations with runtime reality.

### 1.4 Sensitive Sync vs Direct Password Sync Architectural Differences
* **Inquiry**: Are "Sync Sensitive Clips" and "Direct Password & Re-Copy Sync" the same or different?
* **Architectural Breakdown**:
  - **Option 1 (`allow_sensitive`)**: The Master Security Gate.
    - When disabled (`false`), any clip marked `EXTRA_IS_SENSITIVE` on Android (2FA OTPs, authenticator codes, password manager copies) is completely dropped at `core/policy.py`.
    - When enabled (`true`), sensitive clips sync across the mesh with maximum defense-in-depth: 10-second auto-wipe timer, exclusion from Windows `Win+V` history (`CanIncludeInClipboardHistory=0`), blocking from Microsoft Cloud Clipboard (`CanUploadToCloudClipboard=0`), and volatile RAM-only outbox storage.
  - **Option 2 (`direct_password_sync`)**: The Password Manager Usability Override.
    - Relaxes the strict security lockdown specifically for password managers like Bitwarden.
    - Disables the 10-second auto-wipe timer so passwords do not vanish while logging in.
    - Includes credentials in Windows `Win+V` clipboard history.
    - Enables instant repeat copying by bypassing the 90-second deduplication lockout.
  - Dependency Rule: Option 2 requires Option 1 to be active. If Option 1 is disabled, sensitive clips never enter the sync pipeline.

### 1.5 Camera Photo Auto-Backup Location Discovery
* **Inquiry**: Did camera clicks fail to back up to `Temporary Screenshots`?
* **Forensic Evidence**:
  - Live log records show both camera captures transferred losslessly via high-speed direct TCP stream at 14:39:05 and 14:39:09:
    - `<home>\Pictures\Screenshots\Temporary Screenshots\Camera\Photo 2026-11-01 143905_phone.heic` (1,320,177 bytes).
    - `<home>\Pictures\Screenshots\Temporary Screenshots\Camera\Photo 2026-11-01 143909_phone.heic` (1,340,169 bytes).
  - Cause of Confusion: The user checked the root `Temporary Screenshots\` folder. CopyClip automatically places camera photos into a dedicated `Camera\` subfolder (`Temporary Screenshots\Camera\`) to prevent mixing photography with clipboard screenshots and to protect the active Windows clipboard from being overwritten.

## 2. Architectural & UI Enhancements Implemented

### 2.1 Re-Copy Sync Decoupling & Sensitive Sync Dependency Gating
* **Independent Re-Copy Refresh (`allow_recopy`)**: Decoupled re-copy detection from sensitive credentials. Placed `Intentional Re-Copy Refresh` as an independent policy setting under `Clipboard Mesh Policies & Limits`. When enabled, deliberately re-copying the same text or item after 0.3s refreshes it across the entire mesh immediately, bypassing the 90s dedup window.
* **Direct Password Mode (`direct_password_sync`)**: Cleaned up Option 2 to focus exclusively on password manager credentials. Positioned as a strict dependent child of Option 1 (`allow_sensitive`) inside `SENSITIVE CREDENTIALS & PASSWORD SYNC (EXTRA_IS_SENSITIVE)`:
  - Option 2 (`Direct Password Mode`) is indented with a visual connector (`└─`).
  - When Option 1 is unchecked, Option 2 is automatically set to `False` and its checkbutton is placed into `state="disabled"` with muted text colors. The auto-wipe timer entry is also disabled.
  - When Option 1 is checked, Option 2 and the timer entry become `state="normal"`.
  - Added clear explanatory labels distinguishing the Master Security Gate from the Password Manager Mode.

### 2.2 Camera Photo Custom Location Field in Dashboard Settings
* Added a dedicated configuration section under `Auto-Backup Mobile & Tablet Camera Photos` in `windows_app/dashboard.py`.
* Provides an Entry field showing `Default Camera Backup Folder:` and a `Browse...` button opening `filedialog.askdirectory`.
* Wired `new_cfg["camera_backup_dir"]` into `save_and_apply()` with live dynamic hot-reload on the running `Hub`.

### 2.3 One-Click Quick Folder Button for Camera Photos
* Added `[📷 Camera Photos]` button to `QUICK SCREENSHOT FOLDERS` in `windows_app/dashboard.py`.
* Clicking the button reads the configured camera folder (defaulting to `Temporary Screenshots\Camera`), creates the directory if needed, and opens Windows File Explorer directly.

### 2.4 Contextual Outbox Indicator with Target Node Labeling
* Updated `refresh()` in `windows_app/dashboard.py`:
  - When outbox has pending items, the sublabel dynamically maps keys (e.g. `node:pixel` -> `Pixel`, `node:phone` -> `S24`, `node:tab` -> `Tab S10`).
  - Displays `1` with sublabel `Queued (Pixel)` in amber warning text.
  - When outbox is empty, displays `0` with sublabel `Outbox Queued` in muted grey.

### 2.5 Session Delivered Labeling Alignment
* Changed stat banner label from `Clips Delivered` to `Session Delivered` with current uptime throughput framing.

### 4.3 Codebase Improvements Implemented
* **Continuity Stamp Isolation (`core/hub.py`)**: Fixed false relay attribution where a standalone Windows laptop re-copy was logged as `phone (via laptop) -> phone`. Stamped nodes now only correlate if both the source node and the stamp node share the same `SyncDomain`.
* **Image Payload Log Clarity (`core/hub.py`)**: Changed `log.info` in `_deliver_to_node` to format image payloads as `X bytes [image]` instead of misleading `chars`.
* **Reverse Stream Listener Log De-duplication (`nodes/android_node.py`)**: Demoted repeated `STREAM-PORT` announcements to `DEBUG` when the port has not changed, eliminating 3x duplicate `INFO` log lines on connect.
* **Instant Shell Notification on File Arrival (`nodes/windows_node.py`)**: Added `ctypes.windll.shell32.SHChangeNotify` (`SHCNE_CREATE` and `SHCNE_DELETE`) on screenshot and camera photo disk writes. Notifies the Windows Shell immediately, eliminating 1 to 2 seconds of visual lag in open File Explorer windows caused by asynchronous directory polling.

* **Laptop SSD Stat** (`17:34:16.661`): File written to disk at `Temporary Screenshots`.
