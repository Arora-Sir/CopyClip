## 1. Problems Investigated

Five distinct issues and user-reported anomalies were investigated and resolved:

1. **Google Authenticator Code Drop (Sensitive Clips)**:
   - *Symptom*: Tapping an OTP tile in Google Authenticator copied the code to the phone's local clipboard, but it never synchronized to the laptop or Pixel. However, copying the exact same code a second time from Samsung's clipboard history panel synced it immediately.
   - *Requirement*: Enable sensitive synchronization securely with opt-in control, zero disk persistence, and automatic clipboard wiping.

2. **Windows Clipboard History (Win+V) Blank Tile**:
   - *Symptom*: When the auto-wipe countdown finished on Windows, an empty white rectangular card appeared at the top of the `Win+V` clipboard history panel.
   - *Requirement*: Wipe the clipboard cleanly and anonymously in the background without creating any placeholder card in `Win+V`.

3. **Timer Supersession Race Conditions**:
   - *Symptom*: If a sensitive clip was copied (arming a 10s wipe timer) and the user immediately copied normal text, an image, or made a local copy, the pending timer continued running and silently wiped the new content upon expiry.
   - *Requirement*: Any subsequent copy (non-sensitive text, another sensitive OTP, an image, or a local copy) must immediately cancel and supersede any pending wipe timer across all mesh nodes.

4. **Taskbar Feather Icon Reversion**:
   - *Symptom*: CopyClip's taskbar icon intermittently showed the default Tcl/Tk red/blue feather icon instead of the custom CopyClip icon.
   - *Requirement*: Ensure the custom taskbar icon displays reliably under all Windows 11 launching conditions.

5. **Dashboard "1 Outbox Queued" Discrepancy**:
   - *Symptom*: The dashboard status header permanently displayed "1 Outbox Queued" in amber warning text even when all three devices were online, fully synchronized, and the outbox had zero pending files.
   - *Requirement*: Report the true live active outbox backlog count (`0` in muted grey when synchronized, switching to amber warning only when an actual queue backlog exists).

## 2. Root Cause Analysis

### 1. The Google Authenticator Extra & Samsung Clipboard Quirk
- On Android 13+ (API 33+), password managers and 2FA authenticators attach `ClipDescription.EXTRA_IS_SENSITIVE = "android.content.extra.IS_SENSITIVE"` as a `PersistableBundle` extra.
- `ClipBridge.java` detected this extra and flagged `sensitive=true`.
- `core/policy.py` dropped all sensitive clips unconditionally because no opt-in policy existed.
- When the user opened Samsung Keyboard's clipboard tray and tapped the item, Samsung's system UI created a generic `ClipData.newPlainText()` item without re-attaching the source app's `PersistableBundle` extra. Hence, `isSensitive` was `false` on the second copy, allowing it to pass through policy.

### 2. Windows Clipboard History Empty String Artifact
- Previously, `_wipe_sensitive()` invoked `winclip.write_text("")`.
- `write_text` called `user32.SetClipboardData(CF_UNICODETEXT, b"\x00\x00")`.
- Windows Clipboard History (`Win+V`) creates a new history entry whenever `SetClipboardData()` is called with data, even if that data is an empty string.
- Calling Win32 `user32.EmptyClipboard()` inside an open/close cycle *without* calling `SetClipboardData()` clears the clipboard completely without generating a Windows Clipboard History card.

### 3. Wipe Timer Lifecycle Gaps
- In `nodes/windows_node.py`, `self._wipe_timer` was only cancelled when another sensitive write arrived. Non-sensitive text writes, image writes, and local user copies left the timer running in the background.
- In `android/ClipBridge.java`, `doSet()`, `doSetImage()`, and the poll loop (local copies) did not cancel `pendingWipeFuture`.

### 4. Windows AppUserModelID Timing & DWM Frame HWND
- Tkinter's default window class icon is the feather (`wish.exe` / `tk86t.dll`).
- Windows Explorer associates taskbar buttons via `AppUserModelID`. If `SetCurrentProcessExplicitAppUserModelID` is called after Shell APIs or Tk windows have already started, Explorer ignores it.
- Furthermore, `root.winfo_id()` resolves the inner client HWND, not the top-level DWM window manager frame (`root.wm_frame()`). Calling `WM_SETICON` must target `wm_frame()`, `GetParent()`, and `winfo_id()` to ensure the taskbar button updates under Windows 11.

### 5. Cumulative Stats vs. Live Outbox Backlog
- `hub.stats["queued"]` is a cumulative historical counter incremented every time any item enters the outbox over the entire process lifetime; it is never decremented.
- The dashboard was calling `stat_queue_val.set(str(stats.get("queued", 0)))`.
- The live active backlog is `status.get("outbox", [])` (`self.outbox.keys()`).

## 3. Implementations & Architecture

### 1. Opt-in Policy & Wire Protocol (`core/policy.py`, `config.json`, `nodes/android_node.py`, `android/ClipBridge.java`)
- Added `"allow_sensitive": true` and `"sensitive_wipe_s": 5.0` (customized by the owner from the 10.0s default for tighter security) in `config.json`.

- `core/policy.py`: Permits sensitive clips when `self.allow_sensitive` is enabled.
- Wire protocol extended with two verbs:
  - `CONF <base64>`: Sends JSON configuration (`allow_sensitive`, `sensitive_wipe_s`) on connection and hot-reload. Android replies `ACK conf`.
  - `SETS <base64>`: Writes sensitive text to Android's clipboard and arms on-device auto-wipe.
- Rebuilt `bin/clipbridge.dex` (32.7 KB) via `android/build_dex.ps1`.

### 2. Outbox Volatile RAM Guard (`core/outbox.py`)
- Sensitive payloads are routed to `self._sensitive_entries` (in-memory dictionary).
- Strictly excluded when writing `outbox.json` to disk. If the machine loses power or CopyClip restarts, sensitive credentials leave zero trace on disk.

### 3. Windows Endpoint Hardening & Clean Wipe (`winclip.py`, `nodes/windows_node.py`)
- `winclip.write_text_sensitive()` sets `CF_CAN_INCLUDE_IN_HISTORY = 0` (omitted from `Win+V`) and `CF_CAN_UPLOAD_TO_CLOUD = 0` (blocked from Microsoft Cloud Clipboard).
- Added `winclip.clear_clipboard() -> int`: calls `user32.EmptyClipboard()` without `SetClipboardData()`, leaving zero cards in `Win+V`. Returns sequence number so `_wipe_sensitive()` can stamp `self._own_write_seq = new_seq` to suppress echo callbacks.

### 4. Multi-Path Timer Supersession
- Windows (`nodes/windows_node.py`):
  - Image writes, non-sensitive text writes, and sensitive writes cancel and clear `self._wipe_timer`.
  - `_on_change()` cancels and clears `self._wipe_timer` when `winclip.sequence_number() != self._own_write_seq` (local user copy).
- Android (`android/ClipBridge.java`):
  - Added `cancelSensitiveWipe()` helper.
  - Invoked from `doSet()`, `doSetImage()`, `scheduleSensitiveWipe()`, and poll loop on user local copies.

### 5. Windows Taskbar Icon Fix (`windows_app/dashboard.py`, `windows_app/tray.py`, `copyclip.py`)
- Added top-level `SetCurrentProcessExplicitAppUserModelID("me.mohit.copyclip")` before any Shell/Tk initialization.
- In `_apply_win11_attributes()`, resolved `wm_frame()`, `GetParent()`, and `winfo_id()`, sending `WM_SETICON` (`ICON_BIG` and `ICON_SMALL`) to all handles.

### 6. Dashboard Live Backlog Display (`windows_app/dashboard.py`)
- In `refresh()`, reads `active_queued = len(status.get("outbox", []))`.
- Retained reference to `stat_queue_label`, updating color to `WARNING` (amber) when `active_queued > 0` and `TEXT_MUTED` (grey) when `active_queued == 0`.
- Added "Auto-Wipe Timer (seconds)" configuration input field in the dashboard policy card with live hot-reloading.
