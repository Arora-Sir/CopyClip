## 3. Pixel 1 Boot Automation (Tasker)

### 3.1 Problem

Android 10 has no persistent Wireless Debugging pairing (introduced in Android 11). Every
cold reboot resets service.adb.tcp.port to 0. The laptop cannot reach the device until port
5555 is manually re-enabled over USB.

### 3.2 Shell Scripts Deployed to Pixel

**Location on device: `/sdcard/Tasker/copyclip_boot.sh`** (fires at Boot, Root):

```
#!/system/bin/sh
setprop service.adb.tcp.port 5555
stop adbd
start adbd
sleep 3
SHIZUKU_APK=$(pm path moe.shizuku.privileged.api | head -n 1 | cut -d: -f2)
SHIZUKU_LIB=$(dirname "$SHIZUKU_APK")/lib/arm64/libshizuku.so
if [ -f "$SHIZUKU_LIB" ]; then
    "$SHIZUKU_LIB" &
fi
sleep 4
getprop service.adb.tcp.port
ps -A | grep shizuku_server | head -3
```

**Location on device: `/sdcard/Tasker/copyclip_watchdog.sh`** (fires at Device Unlock, Root):

```
#!/system/bin/sh
PORT=$(getprop service.adb.tcp.port)
if [ "$PORT" != "5555" ]; then
    setprop service.adb.tcp.port 5555
    stop adbd; start adbd
fi
if ! ps -A | grep -q shizuku_server; then
    SHIZUKU_APK=$(pm path moe.shizuku.privileged.api | head -n 1 | cut -d: -f2)
    SHIZUKU_LIB=$(dirname "$SHIZUKU_APK")/lib/arm64/libshizuku.so
    [ -f "$SHIZUKU_LIB" ] && "$SHIZUKU_LIB" &
fi
```

**XML artifacts saved at:**
- `<scratch>\scratch\CopyClip_Boot.prf.xml`
- `<scratch>\scratch\CopyClip_Watchdog.prf.xml`

### 3.3 Tasker Profiles State

| Profile | Trigger | Status |
| :--- | :--- | :--- |
| CopyClip_Boot | Device Boot | ON |
| CopyClip_Watchdog | Device Unlock | ON |
| Wireless_ADB_Boot | (old) | OFF - disabled |

### 3.4 Shizuku App Settings (Pixel 1 Only)

Keep both "Start on boot" and "Watchdog" ON in the Shizuku app. These are complementary to
Tasker, not in conflict. Shizuku's own startup does not re-enable port 5555; that part
requires Tasker's script.

### 3.5 Tasker XML Lesson Learned

Multi-line shell scripts embedded inside Tasker XML cause silent import failures when the
script contains quotes, &&, or newlines. Reliable pattern: store scripts as .sh files on
/sdcard/Tasker/ and call them from Tasker with a single shell line, Use Root enabled.

- shizuku_server process alive
- App shows "Wireless ADB active" (green)
- All four mesh nodes connected

## 4. Android App Status Fix

### 4.1 Root Cause

On Pixel 1, Shizuku grants UID 0 (root via Magisk). ClipBridgeService.kt's
requireShellUid() guard rejects this (only UID 2000 / shell is accepted), reporting:
  `refused: Shizuku granted uid=0, not shell (2000)`

The old statusOf() mapped `refused:` to Status.ManualOnly (orange), which was wrong.
Sync was working fine via Wireless ADB (ClipBridge.dex runs under shell UID 2000).

### 4.2 Files Changed

**android_app/.../ui/MainScreen.kt** - statusOf() function:
- Removed Status.ManualOnly entirely
- Mapped "refused:" + "not started" to Status.WirelessAdb (green)
- Updated subtitle to: "Connected to laptop hub (Wireless ADB on port 5555) Auto-sync active"

**android_app/.../service/SyncForegroundService.kt** - formatNotificationStatus():
- "refused:" -> "Syncing via laptop (Wireless ADB)"
- "not started" -> "Syncing via laptop (Wireless ADB)"

APK rebuilt (Gradle assembleDebug, ~26s) and installed on all 3 devices via adb install.

## 5. Truncated Screenshot Fix

### 5.1 Root Cause

Pixel 1 hardware (2016) takes 3-4 seconds to flush large PNGs to disk. The old
checkScreenshots() read files before the write was complete, missing the IEND trailer.

### 5.2 Files Changed

**android/ClipBridge.java** (~lines 1175-1260):
- Deadline extended from 2.5s to 8.0s, active polling every 150ms
- isCompleteImage() added: PNG (IEND in last 12 bytes), JPEG (FF D9 in last 2), GIF (0x3B last), WebP (RIFF size match)
- No transmission until isCompleteImage() returns true

**bin/clipbridge.dex** recompiled (30,768 bytes), pushed to all 3 devices.

Verified: 1,734,625 byte screenshot arrived byte-perfect with valid IEND trailer.

## 7. Things That Were Tried and Did Not Work / Were Reverted

### 7.1 CopyClip App on S24 Ultra and Tab S10 Ultra - REVERTED

Tried for reboot survival. Samsung devices on Android 11+ already survive reboots via
Wireless Debugging pairing with no app needed. Reverted to plain ADB transport. App
uninstalled from both. Lesson: check each device individually, not uniformly.

### 7.2 Automatic Send Clip on Background Change - PERMANENTLY IMPOSSIBLE

On Android 10, background clipboard-change listeners never fire while backgrounded.
The notification is denied before app code runs. No mechanism exists on this Android version.
Send Clip is permanently manual (tap-triggered only).

### 7.3 Theme.NoDisplay Activity for Send Clip - FIXED

Theme.NoDisplay never creates a window, so Android's clipboard-focus exemption never triggers.
Fixed: real visible activity + onWindowFocusChanged(true) gate.

### 7.4 Tasker XML Inline Multi-Line Scripts - FIXED

Silently fails on import. Use external .sh files on /sdcard/Tasker/ instead.

## 8. Known Limitations (Cannot Be Fixed)

### 8.1 Pixel 1 Reboot Survival is Not Guaranteed

One boot test saw port 5555 auto-restore with unknown cause. Do not rely on this.
Tasker scripts remain the authoritative solution. Keep rearm_wireless_adb.bat handy.

### 8.2 Root Clipboard Writes - Impossible on Android

Android OS enforces clipboard access to UID 2000 (shell) only. UID 0 (root) gets
SecurityException. The in-app TCP bridge on Pixel 1 will always refuse. Permanent
constraint of the Android OS, not a bug, not fixable.

### 8.3 Samsung Continuity Degrades Under VPN

Samsung uses Wi-Fi Direct channels that can degrade with persistent VPN (Tailscale).
CopyClip probes for this and falls back to direct dual-write after 3 missed confirmations.

### 8.4 Windows Snipping Tool Duplicate in Win+V - Not a CopyClip Bug

Windows 11 25H2 regression. Two clipboard entries per screenshot with both Snipping Tool
auto-settings on. Reproduced with CopyClip fully stopped. Not fixable here. Workaround:
disable Snipping Tool "Automatically save original screenshots"; CopyClip replicates the
save via screenshot_backup_dir.
